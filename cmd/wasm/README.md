# WASM Bridge

This directory contains the Go WebAssembly (WASM) bridge that provides a storage layer for the browser-based mode of Quantlete.

## Architecture

The WASM bridge provides the same functionality as the Go HTTP API but runs entirely in the browser. It uses sql.js (SQLite compiled to WASM) with OPFS for persistence.

```
┌──────────────────────┐     ┌──────────────────────┐
│   TypeScript UI      │     │   Go WASM Bridge     │
│                      │────▶│                      │
│  - React components  │     │  - Same services     │
│  - Data hooks        │     │  - Same storage      │
└──────────────────────┘     └──────────────────────┘
                                      │
                                      ▼
                             ┌──────────────────────┐
                             │   sql.js + OPFS      │
                             │   (in-browser DB)    │
                             └──────────────────────┘
```

## Key Files

- `main.go` - Entry point, initialization, and registration
- `helpers.go` - JSON encoding, error handling, validation
- `activities.go` - Activity-related WASM exports
- `dashboard.go` - Dashboard statistics exports
- `stats.go` - Best efforts, Eddington, training load
- `gear.go` - Gear management exports
- `segments.go` - Segment and effort exports
- `photos.go` - Photo storage exports
- `maintenance.go` - Component maintenance, settings, zones
- `challenges.go` - Challenges and training goals
- `sync.go` - Sync history management
- `athletes.go` - Athlete data and metrics
- `rewind.go` - Year-in-review statistics
- `algorithms.go` - Computation functions (normalized power)

## Conventions

### WASM Export Annotations

Functions are exported to JavaScript using special comment annotations:

```go
// getActivities retrieves paginated activities
// Called from JS: goStorage.getActivities(filtersJSON)
//wasm:export
func getActivities(this js.Value, args []js.Value) interface{} {
    // ...
}
```

The `//wasm:export` annotation marks a function for export. The function name becomes the JS method name (camelCase preserved).

Additional annotations:
- `//wasm:export methodName` - Export with custom method name
- `//wasm:category CategoryName` - Group functions in documentation

### Bridge Pattern

All state is stored in the global `bridge` variable, a `WasmBridge` struct:

```go
var bridge *WasmBridge

type WasmBridge struct {
    db                 *storage.DB
    athleteID          int64
    activities         *storage.ActivityRepository
    activityService    *services.ActivityService
    // ... other repositories and services
}
```

All WASM functions access state through `bridge.*`:

```go
func getGear(this js.Value, args []js.Value) interface{} {
    result, err := bridge.gearService.List(ctx, input)
    // ...
}
```

### Response Format

All WASM functions return JSON with a consistent structure:

**Success:**
```json
{"ok": true, "data": {...}}
```

**Success (paginated):**
```json
{"ok": true, "data": [...], "total": 100, "page": 1, "per_page": 50, "total_pages": 2}
```

**Error:**
```json
{"ok": false, "error": "error message"}
```

Use the helper functions:
- `dataJSON(data)` - Success with data
- `successJSON(message)` - Success with message
- `errorJSON(err)` - Error response
- `toJSON(map)` - Custom response structure

### Error Handling

Always use `defer recoverPanic(funcName)` at the start of each function to catch panics and return proper errors:

```go
func myFunction(this js.Value, args []js.Value) interface{} {
    defer recoverPanic("myFunction")
    // ...
}
```

### Input Validation

Use the validation helpers:
- `ensureInitialized()` - Check if DB is ready
- `ensureAthleteID()` - Check if athlete is set

### JSON Parsing

Parse JSON arguments using:

```go
var req struct {
    Page    int    `json:"page"`
    PerPage int    `json:"per_page"`
}
if len(args) > 0 && args[0].String() != "" {
    if err := json.Unmarshal([]byte(args[0].String()), &req); err != nil {
        return errorJSON(fmt.Errorf("parsing filters: %w", err))
    }
}
```

## Code Generation

### WASM Registration

Function registration is auto-generated by:
```bash
just generate-wasm
```

This parses `//wasm:export` annotations and generates registration code.

### TypeScript Types

TypeScript interfaces matching Go types are generated by:
```bash
just generate-ts-types
```

This generates `web/src/lib/wasm/types.gen.ts`.

## Building

Build the WASM binary:
```bash
GOOS=js GOARCH=wasm go build -o web/public/quantlete.wasm ./cmd/wasm/
```

Or use just:
```bash
just build-wasm
```

## Testing

The WASM module shares services and storage with the main Go codebase, so most logic is tested via standard Go tests:
```bash
go test ./internal/...
```
